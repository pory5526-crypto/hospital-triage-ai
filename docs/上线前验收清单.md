|---|---|---|---|
| 3.1 | 网页端 · 本机 | `http://127.0.0.1:8000` | ✅ |
| 3.2 | 网页端 · 局域网 | `http://192.168.5.79:8000` 本机已验证 | ⚠️ 需防火墙放行后其它设备才可访问 |
| 3.3 | 网页端 · 手机 | 同 WiFi 打开局域网地址，自动全屏 | ⬜ 待真机确认 |
| 3.4 | 小程序 · 模拟器 | 微信开发者工具导入 `miniprogram/` | ⬜ 待导入 |
| 3.5 | 小程序 · 真机 | 改 `utils/config.js` 为局域网 IP 后预览 | ⬜ 待真机确认 |

**3.2 的阻塞点**：Windows 防火墙「公用网络」默认拦入站，需管理员执行一次：

```powershell
New-NetFirewallRule -DisplayName "医院智能客服 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Any
```

**注意**：局域网 IP 换网络后可能变（当前 `192.168.5.79`）。小程序端写死在 `miniprogram/utils/config.js`，换网后要同步改；网页端不受影响（相对路径）。

## 九、上线判定

**当前结论：可以进入内部演示与试点准备，不可直接对患者开放。**

放行前必须补齐 3 件事：

1. 换掉示例数据（科室/医生/知识库/分诊规则），并经医生复核；
2. 生成正式 HTTPS 域名 + 部署到能对外访问的服务器（医院内网或云）；
3. 分诊测试集扩到 300+ 真实问法，重跑 `acceptance_check.py`。

其余项（并发压测、UAT、试点）按 PRD 的节奏推进即可。
